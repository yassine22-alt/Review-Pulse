# Five-minute assisted-product walkthrough

Use the public thin-line bungalow `data/real_plans/label-study/uk-proposed.pdf`
and its saved trained extraction `runs/native-label-study/uk-proposed/building.json`.
This is a UK drawing used for illustration, not a claim that a selected foreign
code governs it. Use development material only. Never use the fourth document
for demos, editing practice or tuning after its recorded single test.

**Prepare before the timer.** Start `rp serve --port 8081`. Upload/analyse the
drawing once (or use a local project with the saved trained result), then upload
the development requirement document. Have the source, reviewer name and any
real dimension/schedule citations ready. The published text in the existing
`eight-rule-assisted-profile.json` is the source for the IRC example; its old
reviewed facts are scenario attestations, not automatic perception output.
Do not make hosted calls simply to reproduce cached demonstrations.

**0:00–0:45 — source and plan.** Open Inputs, show the drawing and source edition,
then Requirements. Explain that classification chooses numeric drafting or an
expert formalization queue; it does not decide compliance. Choose an original
source such as the hallway-width obligation, with its parent context visible.
If it queues, keep it queued in the demonstration rather than switching to an
unlabelled paraphrase or calling it an automatic draft.

**0:45–1:45 — draft/queue.** Read the clause. For a supported numeric draft,
show the copied threshold, unit and applicable scope, and the closed catalogue
fact choice. For the IRC example, subject ownership/rounded equivalent/context
may require formalization: show the exact blocker. A blank queue is not a model
interpretation. The 12 validated thermal development rows can illustrate the
narrow drafting output, but they are not facts extracted from this floor plan.

**1:45–3:00 — timed edit.** Enter the reviewer name, start the timer and inspect
source meaning. Correct one justified field or use the expert editor to supply
a complete rule. Pause for interruptions. Validate and save; show the recorded
diff and time, including any rejected save. A formalized clause counts as a
rewrite, not one edit because it was pasted once. If its meaning cannot be
validated, stop with needs-review and show why. Do not fabricate a successful
rule to fit the presentation time. This is a scripted walkthrough, not a promise
that expert formalization of an arbitrary clause takes 75 seconds.

**3:00–4:00 — plan facts and approval.** Show which facts came from the trained
pipeline and which remain missing or reviewer-attested. Keep clear width/height
unknown when only nominal sizes exist. Do not confirm a whole inventory because
some detected rooms look right. Acknowledge meaning and approve only the validated
interpretation; this does not verify its missing measurements.

**4:00–5:00 — verdict and evidence.** Run check. Show the exact clause, approved
rule, source citation, dependent entities and missing-evidence trace. An unresolved
verdict is the correct demonstration when the drawing cannot settle the rule.
Do not force a pass or violation. Show the local effort report, split by draft and
formalization queue. It remains empty until a real reviewer completes a session.
If using the old eight-target evidence report as backup, label it archived:
7/8 readings, 7/7 full rewrites, 2/8 scenario-assisted decisions, 5/8 validation
blocks, 1/8 request rejection; zero gold violations means undefined false-pass
rate. Do not describe that report as a successful eight-rule automatic demo.

The demo's honest stopping points are needs-review, missing evidence or a
supported verdict. Its purpose is to make that distinction inspectable, not to
hide the current coverage limitation. [Reviewer instructions](assisted-review-workflow.md).
