## Additions made during implementation (each is general, not tied to a test case)

| ID | Decision | Why |
|---|---|---|
| A1 | Normalise drawing styles before perception: arcs rebuilt from line chains / polylines; window symbols, door leaves and dimension graphics recognised geometrically and kept out of wall pairing | Exporters draw the same thing many ways and layer names are often missing; a layer-free plan must work |
| A2 | Dimension-pair thresholds expressed in units of dimension-text height | The same test then works on PDF paper space and DXF drawing units at any scale; also recovers the scale of unitless DXF |
| A3 | Two wall pieces cannot occupy the same material; snapping can never collapse a wall | Square piers can otherwise be read in two orientations |
| A4 | Short wall pieces survive when attached to another wall or flanked by collinear walls (piers between openings, pilasters) | Only isolated fragments are noise |
| A5 | A door symbol must span its gap (hinge at one jamb and closed end at the other); arcs are assigned to gaps best-first | Prevents a neighbouring window gap from stealing a door arc |
| A6 | Filled PDF paths become filled polygons (closed subpaths) | Solid walls, columns and pilasters are drawn as fills |
| A7 | Findings evaluation uses an oracle (true) model: planted errors must be found on the oracle; real-vs-oracle differences are perception errors | Consequential findings are not false alarms; errors are attributed to the right stage |
| A8 | The example requirement document `docs/requirements_example.md` is a test fixture, not a regulation | Thresholds must come from a document; the real one replaces it |
| A9 | Real-world clutter is separated from walls by physical and drawing rules: (a) a face bounding a wall on one side takes a second body only if both still make one plausible wall; (b) parallel bodies glued side by side beyond the maximum thickness keep only the dominant-thickness piece; (c) wall clusters under 3 m across, disconnected from the wall network (collinear gaps of an opening count as connected), are objects; (d) faces from two different small nested closed outlines are an object symbol | Wardrobes, counters, sofas, bathtubs drawn against walls otherwise become 0.15-0.6 m "walls" |
| A10 | Layer identity is learned when layer names say nothing: layers whose lines are mostly wall faces (>= 50% usage) are the wall layers; pass 2 re-runs wall detection on them | Numeric or arbitrary layer names still separate furniture from walls |
| A11 | Regular textures (exploded hatch patterns, stair treads) are tagged and kept out of wall pairing: neighbour-built families, >= 4 evenly spaced levels, short alike strokes on one layer | Hatch strokes 5-10 cm apart otherwise pair into thin walls |
| A12 | I4 drafting asks the LLM for a small frame (property, subject, rooms, comparison, number as written); code maps it to the registry, converts units, derives checkability and cross-checks comparison words | A local 7B model is reliable at the frame, not at assembling a whole rule |
| A13 | Default LLM backend is local and open-source (Ollama, Qwen2.5-7B-Instruct, Apache-2.0), temperature 0 and a fixed seed | Free, offline, reproducible; nothing leaves the machine |
| A14 | Raster walls / doors / windows from a U-Net (ResNet34, ImageNet weights) trained on CubiCasa5K; a page is rescaled so its wall thickness matches the training median (14 px), then predicted on overlapping tiles. The thickness is measured on the model's own wall mask from two downscaled probes (longest side 1024 px and half), never from ink, and never from an upscaled pass | Scans vary in resolution and drawing scale; matching wall thickness makes the model resolution-independent. Ink-based thickness measured outlines (6.5 px for 18 px walls) and an upscaled pass makes the model mark only outlines, which then confirms the wrong size. CubiCasa is CC BY-NC: non-commercial only |
| A15 | OCR backend PaddleOCR (PP-OCRv6, CPU), EasyOCR as fallback; each tile read at 0/90/270/180 degrees, duplicates merged preferring the pass in which the box was upright (engines also read turned boxes, which hides the true reading direction) (spike S-D) | On 25 hand-transcribed CubiCasa crops: CER 0.12 vs 0.61 (EasyOCR missed most small, rotated and upside-down labels) |
| A16 | Rule baseline ink = local (Sauvola) OR global (Otsu) darkness; the line-removing opening is sized from the thinnest wall class (stroke-width peaks clearly heavier than the pen weight), not the dominant one | Solid or grey wall fills are walls, not outlines; exterior walls are often twice the partitions and a dominant-width kernel erases every partition |
| A17 | Without recognised doors (rules only), rooms come from walls closed over gaps up to 4.5 wall thicknesses; such rooms carry no door edges | A 0.9 m door is ~4.5 wall thicknesses; unknown connectivity is reported as unknown, not guessed |
| A18 | Default raster walls are the model's alone; fusion (model plus rule-wall components overlapping it < 40%) is available but off | Measured on 100 CubiCasa test plans: fusion raised wall recall 0.979 -> 0.983 but dropped precision 0.930 -> 0.735 and room F1 0.873 -> 0.819 (the extra rule "walls" are furniture and text) |
| A19 | Scan scale: dimension consensus (R7, with OCR text and LSD line segments as primitives; LSD primitives carry no stroke width, since LSD's support width is not the stroke width) when it succeeds; otherwise a wall-thickness prior (dominant wall = 0.20 m), method `symbol_prior`, confidence 0.4, tier T3; a scan is never T1 | The prior keeps room sizes plausible for filtering and probing, while metric rules stay capped at WARNING |
| A20 | When scale metadata is missing or implausible (unitless datasets such as ResPlan), the scale is 0.85 m divided by the median drawn door width | Doors are the most standard-sized element on a plan; area metadata gave scales off by 10-100x |
| A21 | R10 seals envelope leaks: erode the exterior by 0.75 m; parts cut off from the sheet border whose mouth is <= 12% of their perimeter become interior, with a warning | Gaps in the outer wall otherwise flood a whole wing with "outside"; wide-mouthed courtyards stay outside |
| A22 | Room evaluation merges open-plan truth rooms that share an unwalled boundary, and builds truth door edges by probing beyond each door's faces; outdoor spaces are not scored | Scores R10 on what geometry can decide, not on labelling conventions |
| A23 | New rules C-D5, C-V2, P-5, P-6; C-V2 takes window heights only from the schedule and is NOT_EVALUATED without them | A plan view does not show heights; never guess a safety-relevant dimension |
| A24 | T4 regression snapshots (10 fixed plans) compared within tolerances; `--snapshot-update` rewrites them for review | Every perception or rule change shows up as a named diff |
| A25 | Room labels come from a data lexicon, not code: `annotate/lexicon/curated.yaml` (13 room types x FR EN DE ES IT NL PT FI SV AR, with abbreviations; a word listed under two types is a load error) plus `mined_*.yaml` generated from real labels (CubiCasa5K train+val: label seen >= 5 times, >= 80% one type). Curated entries win | Labels are language data. On 5,011 CubiCasa test spaces (never used for mining): FR/EN keywords 6.5% correct, curated 85.6%, curated+mined 99.95% |
| A26 | OCR-read labels also match with edit distance (1 edit, 2 from 9 letters) only for cores of >= 5 letters and only when every closest lexicon entry names one room type; never for vector text | OCR misreads long words ("OLOHUOME"); a two-letter abbreviation one edit away is another word (UH vs MH), so short ones are never guessed. 20 OCR'd test scans: 47% -> 51% of spaces correctly labelled |
| A27 | Unmatched label-like notes go to the local LLM (qwen2.5:7b, schema-constrained to the room types + not_a_room, temperature 0, seed 42, disk cache); the result is marked `label_source: llm`, confidence 0.6, and a FAIL never rests on such a room (WARNING "verify room type") | Measured alone on CubiCasa test labels the model is right only 59% of the time (precision 0.68) on Finnish abbreviations, so it is a fallback that keeps the room labelled, never evidence for a FAIL. Off with REVIEWPULSE_LABEL_LLM=0 (tests run with it off) |
| A28 | A bare number stacked against a room label (next line, same orientation, within 1.6 text heights) is the room's stated area; outside 1-300 m2 it is set aside as a note | Plans drop the unit ("MH" over "14.1"); read as a dimension it fed the scale vote. 20 OCR'd scans: bare numbers read as dimensions 27 -> 14, stated areas read 8.8% -> 16.6% of spaces |
| A29 | A presence rule (no label, no tag, ...) never FAILs on a sheet whose text was read by OCR, and a check that names no deciding elements is decided by its subjects (they must be confirmed below T1) | An absence on OCR'd text may be an OCR miss; plan 1191 had 33 such FAILs at T3 |
| A30 | Raster door/window blobs filling < 60% of their rotated rectangle are opened with a disk of 0.3 x their own core thickness and each surviving part gets its own rectangle | A blob merged with stair treads or terrace lines made one oversized rectangle. 100 CubiCasa test plans: oversized window rectangles 42 -> 32, doors 11 -> 8; window rectangle F1 0.791 -> 0.806; masks and rooms unchanged |
| A31 | SVG text: one item per positioned run (`<text>` or each `<tspan>` with x/y), placed, sized and turned through the element transform, width from per-glyph x lists | Exporters (PyMuPDF, Inkscape, CAD) put positions on tspans and rotate with matrices; reading only `<text x y>` stacked every label at one point and the SVG of a T1 PDF fell to T3. Now T1 (8/8 dimension inliers) |
| A32 | Acceptance suite (`eval/acceptance.py`, `scripts/acceptance.py`, `tests/acceptance/`): every input type through the real `rp check` CLI; checks exit, reports, tier, walls/rooms, no unsafe FAIL (metric below T1, presence on OCR text, LLM-typed room) and planted errors (required on vector input, measured on scans) | One command proves the product end to end on each input kind; scans are marked slow (model + OCR) |
| A33 | A sheet that declares itself not to scale (NTS, "not to scale", sans échelle, nicht maßstäblich, sin escala, fuori scala, niet op schaal, sem escala, ei mittakaavassa, ej skalenlig, بدون مقياس, ...) keeps an estimated scale at confidence <= 0.5 (tier T3, metric rules at most WARNING) and gets a warning; DXF model-space units and a user calibration are kept | The drafter says measurements are not reliable; CubiCasa scans carry "EI MITTAKAAVASSA" (colorful/10052 has only that footer and the logo as text) |
| A34 | OCR default: PaddleOCR PP-OCRv6 medium detection + recognition, 4 page rotations, on the GPU when PaddlePaddle sees one (`ocr_device()`), else the CPU; overrides REVIEWPULSE_OCR_DEVICE / _DET / _REC / _ROTATIONS | 8 CubiCasa test scans: GPU 10.2 s/page, labels 39.8% (CPU 229 s/page, 38.6%). Two rotations: GPU 6.5 s, CPU 95 s but -8 to -10 points of labels and most stated areas lost (the text-line classifier fixes 180 deg, not 270 deg text). PP-OCRv6 small recognition: slower and less accurate on both devices. CPU timings measured beside training jobs (upper bounds) |
| A35 | On scans every scale is checked against the doors: when the median of >= 3 detected doors is outside 0.6-1.3 m, the title block's scale is used if doors are plausible under it, otherwise the scale stays at confidence <= 0.5 (T3) with a warning; a user calibration is never overridden. The acceptance suite also requires a T1/T2 sheet to measure its rooms within 10% of the generator's truth | A synthetic PNG got dimension consensus 1:186 at confidence 1.0 (T2): the line detector split each dimension line at its text and three half-lines agreed; rooms came out 3.4x too large and doors 1.63 m. Correct scans have median doors 0.85-0.88 m and measure 0.97 of true area |
| A36 | A dimension text pairs only with the nearest parallel line beside it (within 1 text-height unit of the nearest, so both edges of one stroke count); if that line has no terminators the text gives no scale candidate | On a scan the ticks of the true dimension line were lost while a wall/door edge 10 mm away, with perpendicular jamb lines at both ends, passed as a dimension at half length: three such pairs agreed on 1:186 at confidence 1.0. Vector T1 results and the 230 fast tests are unchanged |
| A37 | Every extracted object owns its provenance: a PDF path split into several primitives gives each one its own `Prov` (contract test `test_provenance_is_never_shared`) | Per-primitive evidence (rule tags, classifier calls) was written into one dict shared by all lines of a path, so the last write won for every sibling: on PDFs drawn with polyline walls the classifier's correct wall calls were overwritten and fusion dropped 10 of 474 rooms. Real CAD PDFs draw most geometry as multi-segment paths |
| A38 | Vector default: the rule pass proposes walls and a LightGBM primitive classifier (43 features incl. the rule results; FloorPlanCAD + generated plans) disposes: a rule wall whose member lines it mostly (> 50% of length) rejects becomes a candidate (`cls other`, `candidate`), a classifier-built wall where no kept wall stands is added, openings are rebuilt and the classifier's door/window components hosted on walls are added (`needs_confirmation`). If it rejects every rule wall, the rule result is kept | FloorPlanCAD test (100): walls length F1 0.283 -> 0.518, doors 0.657 -> 0.901, windows 0.20 -> 0.687. Generated plans: rooms 474/474 on DXF and PDF, planted errors 24/24 (doors 0.999 -> 0.989). The rebuild-only variant (walls from classifier-kept lines only) scores higher FloorPlanCAD walls (0.569) but loses rooms (472/474 on PDF) and doors (0.99 -> 0.88) on generated plans (reports/v4_rebuild). Model data is CC BY-NC (FloorPlanCAD) |
| A39 | A small closed outline (under 3 m across) whose largest inscribed circle is wider than the thickest wall (0.6 m) is an object (bathtub, lift car, counter): its lines never pair into walls and never become learned wall faces. Width is the inscribed circle, not the bounding box | Generated plan 5033 as PDF: the ArchCAD-trained model called a bathtub outline walls and a 1 m2 false room cut the bathroom from 10.1 to 8.5 m2. A first version measured width with the minimum rotated rectangle and broke L- and T-shaped wall bodies drawn as one closed outline; the inscribed circle keeps them (tests in `test_learned_faces.py`) |
| A40 | Escape distances are walked, not drawn: a visibility graph inside each room (`core.geometry.Walkable`) and door-to-door distances to the exit (`_EscapeField`); travel is measured from the farthest point of a room. C-T6 (door swing against the escape direction) ships as a draft template until a document states it | Straight-line distance through walls understated travel. The generator itself placed the flat entrance so that 40 of 40 clean plans broke the 15 m example limit; the entrance now opens into the hall (worst clean plan 14.89 m) |
| A41 | The brief is an input: `rp check --brief` reads a room programme (CSV, XLSX, DOCX, PDF, MD; French and English headers) and K-P1 checks room counts per type and areas (largest to largest, `area_tolerance`). A count shortfall is NOT_EVALUATED while unlabelled rooms exist; with several sheets the programme is not attached and the run says so | Missing or undersized rooms against the client's programme are among the errors reviewers report; a shortfall caused by an unread label is not a design error |
| A42 | Drafted rules carry deterministic wording flags: ranges, permissions ("may", "peut"), and clauses stating both a minimum and a maximum are flagged for the reviewer, whatever the LLM produced | CODE-ACCORD (171 sentences): drafts with the wrong comparison direction and no flag 13 -> 11; among drawing-checkable clauses 2 -> 1. Numbers read correctly 78/105 |
| A43 | The vision-language second reader for scanned labels (qwen2.5vl:7b, `annotate/label_vlm.py`) stays off by default; when on, a re-reading is used only if it agrees with the OCR reading (letter similarity >= 0.6, length ratio 0.5-2) and a FAIL never rests on it | 20 CubiCasa test scans: labels correct 50.8% without and with it. Of 120 words re-read, 81 answers were inventions (a blank crop read "10'x20' Living Room"), all blocked by the gate; 2 became correct labels |
| A44 | ArchCAD (CC BY-NC 4.0, gated) is a second real CAD domain for training and evaluation: JSON modality (entity, line type, arc direction), 1 unit = 14/980 m, split by name hash (5% test, 5% val, 90% train), only slices with walls evaluated. Glass (19) is scored as windows; a window instance is a group of glass lines that touch or run side by side (parallel, overlapping along their direction, within 0.4 m) | One training domain overstated generality: the FloorPlanCAD model reached 0.40 wall F1 on ArchCAD. Grouping by touching alone split each window symbol into its 2-4 panes: 376 "true windows" on the 100 test slices were 111 windows, and one predicted window was credited with 4 |
| A45 | An evaluation that cannot measure what it names fails: `--method learned` without a model stops before scoring, a run where every drawing crashed raises instead of writing a report, and every report counts crashed drawings | The first v6 run wrote a report of zeros (training had stopped; every drawing crashed on the missing model) and its synthetic steps would have scored rules only under the name "learned" |
| A46 | The learned pass falls back to the rule result when the classifier rejects every rule wall; the fallback guards against the classifier only, never against an annotator given true labels | Reference rooms are built from the dataset's true lines through the same pipeline. Where the labels mark no walls (a car park, FloorPlanCAD 0029-0526) the reference fell back to the rule walls and scored bay lines and car outlines as rooms: 15 of 81 FloorPlanCAD reference rooms were false |
| A47 | Fusion keeps a rule wall when the length-weighted mean wall probability of its lines reaches the model's tuned threshold (it was: at least half its length called wall) | Two equal faces, one called wall (0.7) and one not (0.13), tied at a share of 0.5 and stayed: free-standing hatched strips cut a FloorPlanCAD hall (0054-0004) into 8 rooms. The probability keeps what the yes/no call threw away |
| A48 | Glued wall bodies (A9b) are judged on drawn thickness only: a learned face (one line with an assumed thickness) never takes part. In the learned pass the body the classifier believes more is kept, then the more common thickness, then the longer | A learned face's assumed 0.25 m body beside a true 0.35 m wall made them "too thick together" and true walls were dropped: on FloorPlanCAD 0460-0018 v6 lost 23 true wall faces and the room; after the fix 14, and the room is found with its area within 5% |
| A49 | A kept rule wall that pairs a wall face the classifier believes with a line it rejects (a lift car, a fixture or a finish line inside the room) is replaced by the walls rebuilt from believed lines only, when those carry at least 90% of its believed faces; the rule wall stays as a candidate (`replaced: true`) | Rooms on real CAD came out too small: 4.3% of the matched reference area was missing as a thin band along walls, and those walls were mostly a true face paired with a lift car (6.7 m2) or an unlabelled line (3.5 m2). With A50: FloorPlanCAD room areas within 5% 45% -> 59%, ArchCAD 47% -> 54% (default model) |
| A50 | Window lines from the classifier form one window when they touch or lie side by side (parallel, overlapping along their direction, within 0.4 m); one shared test (`core.geometry.side_by_side`) for the pipeline and the ArchCAD truth | Panes of one window symbol do not touch: they are joined only by jamb lines, which the classifier may call wall. Each pane became a single-line group and was dropped (ArchCAD 1a30af18: 1 of 5 windows). Windows F1 with the same model: FloorPlanCAD 0.69 -> 0.81, ArchCAD 0.45 -> 0.69 |
| A51 | Default primitive model: v6 (FloorPlanCAD + ArchCAD + generated plans, text-context features). Adoption rule (D8, refined): a change is adopted when its gains on what reviewers check (rooms, room areas, openings, routes) clearly outweigh its losses, every loss is stated here, and planted errors on generated plans stay all found | Against the previous default (v4, code before A49/A50), 100 test drawings per set: ArchCAD rooms F1 0.37 -> 0.68, room areas within 5% 47% -> 54%, walls 0.40 -> 0.52, doors 0.83 -> 0.91, windows 0.48 -> 0.69; FloorPlanCAD room areas within 5% 45% -> 59%, windows 0.69 -> 0.81, doors 0.90 -> 0.90. Losses: FloorPlanCAD walls 0.544 -> 0.530, FloorPlanCAD rooms F1 0.747 -> 0.742 (about 1 room in 66). Generated plans unchanged (rooms 1.000 DXF and PDF), planted errors 24/24. Model data is CC BY-NC (FloorPlanCAD, ArchCAD) |
| A52 | Clauses are drafted as a one-line expression that code parses into the rule, then checked against the sentence and the declared facts, with one repair; anything that still fails is UNRESOLVED with a reason, never a guess | On 60 synthetic sentences with the local 7B model, a correct rule went from 10% (recursive format with an example) to 83%, and a valid-but-wrong rule fell from 70% to 5%. Checks never blocked a correct rule in 250 tries. On 60 real regulation sentences no wrong rule was written (4 before the grounding check). Losses: 3 of 60 drafts are still valid and wrong; the grounding check runs on English only. Asking three times and keeping agreeing answers, and a model as judge, were measured and not adopted (docs/progress/M7) |
| A53 | The plan reader reports stair flights found from their tread lines (a statistical comb model, no layer names or text), with a measurement uncertainty and a confidence calibrated on drawings the fit never saw; the stair list is never declared complete | Synthetic flights with known truth: found 98%, tread depth error median 0.00 cm and at most 0.08 cm. FloorPlanCAD: 57% of labelled stairs found, 88% of detections real, a detection on 12% of drawings without stairs. Calibrated confidence of 0.8 or more is right 97% of the time and keeps 76% of detections. Losses: curved and spiral stairs, tick-mark stairs and flights under four treads are missed |
